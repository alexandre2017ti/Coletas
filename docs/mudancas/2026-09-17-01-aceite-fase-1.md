# Aceite integrado da Fase 1

## Motivo
Concluir a validação dos fluxos locais de acesso, documentos e análise administrativa, distinguindo testes automatizados de envio real de e-mail e homologação física.

## Escopo e simplicidade
Reutilizar serviços, cliente HTTP, componentes FLOWSTACK Brick 0.2.2 e fixtures existentes. Corrigir somente falhas demonstradas pelo aceite. Sem dependências novas. Preservar cadastros da demonstração; testes usam banco descartável separado.

## Arquivos afetados
App.tsx, testes de acesso/aceite, Dockerfile web, documentação e demais arquivos identificados nos resultados desta rodada.

## Impacto e migração
Aviso da demonstração recebe região acessível. Container web inclui o validador compartilhado com mobile. Sem nova migration nesta correção. Recuperação real exige SMTP externo e dispositivos físicos exigem participação do responsável.

## Validação e testes
- 150 testes .NET aprovados; cobertura 90,28% de linhas. Gate local de 80% aprovado; cobertura não mede percentual de erros possíveis.
- 72 testes web desktop/viewport mobile aprovados; 2 opt-in ignorados na suíte simulada. Aceite real separado aprovado em 1,2 minuto, incluindo cadastro, documentos, aprovação, correção, reprovação e bloqueio concorrente (200/409, único evento).
- Web build/lint e formatação .NET aprovados. Três testes mobile, TypeScript e bundles Android/iOS aprovados.
- Capturas de conta aprovada e análise administrativa inspecionadas, somente com fixtures; sem alegar certificação de acessibilidade.
- Auditoria Premium mantém quatro achados estáticos conhecidos em Button href/Trigger/Close compostos dos fluxos anteriores; não declarar auditoria estrita limpa. Os testes de interação correspondentes passaram.
- Build da imagem web local bloqueado pela conexão do WSL ao Docker Hub (`no route to host`). Web validada pelo Vite local; imagem precisa da confirmação do CI.

## Demonstração e preservação
API atualizada por runtime local em cache e readiness 200 via proxy 5173. Banco manteve exatamente um usuário antes/depois; sem apagar cadastro. Backup privado em `/tmp/coletas-before-phase1-20260917.dump` dentro do container PostgreSQL; imagem anterior `coletas-preview-api:before-phase1-20260917`. Esse backup local não substitui backup externo de produção. As remoções de dados ocorreram exclusivamente no banco descartável `coletas_phase1_acceptance` durante reexecuções.

## Revisão de simplicidade
Ponytail-review: reaproveitados serviços, cliente e controles existentes; tradução estreita de conflito no DbContext evita filtros duplicados. Sem bibliotecas novas nem nova arquitetura. Revisão não substitui os testes de segurança e concorrência acima.

## Rollback
Reverter este conjunto de mudanças; restaurar imagem anterior da demonstração se necessário. Não excluir volumes, documentos nem cadastros. Banco descartável de aceite não contém dados operacionais.

## Pendências
SMTP externo depende de escolha/configuração do provedor (usuário informou não possuir). Android físico depende de ferramentas USB/cliente compatível e execução acompanhada; iOS sem aparelho. Publicação no GitHub e resultado do CI serão registrados após confirmação. API de proteção administrativa do GitHub retornou 403; consulta da branch informou `protected: false`, sem comprovar ausência de rulesets adicionais.
