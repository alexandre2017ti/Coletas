# Fase 0 — Fundação técnica

Status: implementação concluída; aceite integrado pendente de Docker Engine.

## Objetivo e motivo
Criar uma base compilável para o monólito modular, web e mobile, com ambientes reproduzíveis e verificações antes de desenvolver os cadastros. Aplicar as skills csharp-developer e dotnet-core-expert adaptando os exemplos de .NET 8 ao .NET 10 solicitado.

## Escopo e arquivos
`src/`, `tests/`, `apps/`, `infra/`, `scripts/`, `.github/`, arquivos de configuração da raiz e documentação da Fase 0. Não há operação comercial implementada nesta fase.

## Impacto e decisões
Camadas Domain, Application, Infrastructure e Api; Expo para inicializar React Native; migrations executadas por comando explícito; configurações iniciais inseridas por migration, sem usuários ou senhas de demonstração.

## Validação

- 7 testes xUnit aprovados: contrato HTTP, liveness, falha de readiness, OpenAPI, rota desconhecida, validação de conexões e mapeamento de schema/PostGIS.
- Cobertura local: 89,47% em Debug e 89,23% em Release das linhas próprias; migrations/snapshots e geradores OpenAPI excluídos da métrica. Caminho positivo das dependências e aplicação da migration precisam de teste integrado.
- dotnet format --verify-no-changes aprovado.
- Migration InitialFoundation gerada via dotnet ef; SQL idempotente revisado, sem drops no avanço. Modelo sem mudanças pendentes.
- Web: análise estática, build e 4 testes Playwright aprovados (desktop/mobile, disponibilidade/indisponibilidade e largura responsiva). Os testes de UI simulam a resposta HTTP.
- Mobile: TypeScript, compatibilidade Expo, exportação Android e exportação iOS aprovados. Não foram gerados instaladores assinados nem testados aparelhos físicos.
- npm audit: zero vulnerabilidades após ajuste da dependência transitiva mobile.
- YAML do Compose e CI interpretado com sucesso; execução real dos containers pendente. Docker ausente; Podman instalado sem conexão funcional.
- Verificador de documentação executado localmente; workflow remoto ainda não executado.
- API executada em processo local e verificada por HTTP: identificação 200, liveness 200 e readiness 503 com dependências deliberadamente indisponíveis.

## Migração e rollback
Migration inicial cria o esquema de configurações e habilita PostGIS. Em banco descartável novo, `dotnet ef database update 0` reverte a tabela, com perda dos dados dessa tabela. Não executar em banco existente sem revisar backup e script. `docker compose down` preserva volumes; não usar `-v` para parar o ambiente.
